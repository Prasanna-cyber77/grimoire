# Grimoire

Grimoire is a self-hosted MCP server (Streamable HTTP, spec 2025-11-25+) that lets Amazon Alexa+ run a persistent, voice-only tabletop RPG as the Dungeon Master. The server is the game's brain and memory (authoritative state, rules, and dice, all deterministic in code); Amazon Bedrock is its imagination (narration and NPC dialogue seeded with the true game state); Alexa+ is its voice.

## Living World (Phase 4)

The game world advances over time even while the player is away. When they return, the server gives a "while you were away..." recap. This is the project's signature feature.

**All world changes are DETERMINISTIC in code; Bedrock only narrates the recap.**

### Persisted World State (SQLite, survives restart)

- **world_state** per game: turn counter, threat_level (0-10, starts at 0), last_played timestamp
- **ongoing_situations** per game: named situations with countdown ticks until they "fire" (e.g., "Bandits march on the village" fires in 5 ticks, "A grateful merchant prepares a reward" fires in 3 ticks). Each situation defines a deterministic effect when it fires.
- **world_events** per game: append-only log of what changed each tick (human-readable)

### Tick Mechanics (all deterministic, no AI)

- Advancing one tick: increment turn counter, decrement every ongoing situation's countdown; when countdown hits 0, APPLY its coded effect and write a world_events entry.
- Example effects:
  - "bandits" fires → threat_level +3, village_gate location description gains line about bandit campfires, Captain Varek's disposition drops
  - "merchant reward" fires → reward item appears for player, merchant NPC's disposition rises
- Config via env (see `.env.example`):
  - `WORLD_TICK_SECONDS` = real seconds per tick (default 3600 = 1 hour; set low like 10 for demos)
  - `MAX_TICKS_PER_RESUME` = cap on how many ticks a single resume can apply (default 100)

### MCP Tools (all take optional `gameId`, defaults to 1)

| Tool | Description |
|------|-------------|
| `describe_scene` | Returns current scene description for crossroads (reflects world changes) |
| `look` | Look around at current location (optional `location` param, reflects world changes) |
| `get_world_state` | Returns turn counter, threat_level, ongoing situations with remaining ticks, recent world_events |
| `advance_world` | Advance N ticks deterministically (for demo/testing); returns fired events and new world state |
| `resume_game` | Compute elapsed ticks from `(now - last_played) / WORLD_TICK_SECONDS`, capped by `MAX_TICKS_PER_RESUME`, advance that many ticks, set `last_played = now`, return "while you were away" recap. Recap is generated by Bedrock from structured fired events (with graceful fallback to plain bulleted list). |
| `world_config` | Returns current `worldTickSeconds` and `maxTicksPerResume` |

### Example: Resume Game Recap

```json
{
  "recap": "While you were away, bandits arrived at the village gate. Threat level rose to 3. A merchant left a token of gratitude at the square.",
  "firedEvents": [
    {"situationName": "Bandits march on the village", "eventType": "bandits_arrive", "description": "Bandits have arrived...", "effects": {...}},
    {"situationName": "A grateful merchant prepares a reward", "eventType": "merchant_reward", "description": "A reward (Merchant's Token) has been left...", "effects": {...}}
  ],
  "newWorldState": {"turnCounter": 6, "threatLevel": 3, "lastPlayed": "2024-01-01T06:00:00.000Z"},
  "ticksAdvanced": 6
}
```

### Configuration (`.env`)

```bash
# Living World
WORLD_TICK_SECONDS=3600        # Default 3600 (1 hour). Use 10 for fast demos.
MAX_TICKS_PER_RESUME=100       # Safety cap per resume call.

# Narration (Amazon Bedrock)
NARRATION_ENABLED=true
AWS_REGION=us-east-1
BEDROCK_MODEL_ID=anthropic.claude-3-sonnet-20240229-v1:0
# AWS credentials (one required for Bedrock):
# AWS_ACCESS_KEY_ID=
# AWS_SECRET_ACCESS_KEY=
# AWS_SESSION_TOKEN=
# AWS_PROFILE=
# AWS_ROLE_ARN=

# Database
DB_PATH=./data/grimoire.db
```

## Testing

```bash
npm test
```

Tests use a temporary SQLite database and mock Bedrock calls. They verify:
- Tick advancement decrements countdowns and fires events at correct ticks
- Fired events apply effects (threat_level, location text, NPC disposition, items)
- World events persist across server restart
- `resume_game` computes correct ticks, respects `MAX_TICKS_PER_RESUME`, returns recap
- Bedrock is called with structured fired events; fallback works when narration disabled
